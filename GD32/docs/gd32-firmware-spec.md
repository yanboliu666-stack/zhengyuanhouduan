# GD32E230 微型红绿灯 · 固件开发规格书（影子运行）

> 面向对象：负责 GD32 固件与硬件原理图的同事。
> 本规格书是固件开发的**唯一权威依据**。宿主机侧的控制接口层实现见
> [`host/`](../host/)（尤其 [`host/protocol.py`](../host/protocol.py)，是与本规格书
> **字节级一一对应**的参考实现）。改动协议时必须双方同步。

## 1. 定位与边界

本项目是「智能交通信号控制系统」的影子运行（dry-run）执行层：用一块
**GD32E230C8T6** 驱动一个**微型四向红绿灯**（每向红/黄/绿三盏灯，共 12 路），
作为真实信号机的**缩小替身**，观察逻辑决策层（zhengyuan 项目）的相位建议在
「实物」上如何被安全执行。

关键边界（务必理解，不要破坏）：

1. **软请求，非灯色指令**：宿主机**只发相位指示**（「请切到相位 N」），
   **绝不直接下发灯色或配时**。绿灯多久、黄灯多久、全红多久、何时能切，全部由
   **本固件本地裁决**。这与真实信号机的职责完全一致。
2. **执行反馈**：宿主机不假设「灯已切换」，而是通过**状态回读**确认固件实际所处
   相位；固件回读的状态是决策层执行反馈闭环的唯一依据。
3. **安全优先**：最小绿是硬下限（不到时间不许切），最大绿是硬上限（到时间必须切），
   黄灯/全红是清空时序，失联必须黄闪兜底。任何软请求都不能越过这些硬约束。

## 4. 串口物理层与帧协议

### 4.1 物理层

| 项 | 值 |
|---|---|
| 接口 | USART0，异步全双工 |
| 引脚 | PA9=TX，PA10=RX |
| 波特率 | **115200** |
| 数据位 | 8 |
| 校验 | 无（None） |
| 停止位 | 1 |
| 电平 | 3.3V TTL（勿接 5V 电平的 USB 转 TTL） |
| 主从 | 宿主机为主（主动发起命令），GD32 为从（被动应答） |

### 4.2 帧结构

```
┌──────┬──────┬──────┬──────┬───────────────┬──────────────┬──────┐
│ 0x7E │ ADDR │ CMD  │ LEN  │ PAYLOAD(LEN)  │ CRC16(2B,LE) │ 0x7E │
│ FLAG │  1B  │  1B  │  1B  │    0..255 B   │              │ FLAG │
└──────┴──────┴──────┴──────┴───────────────┴──────────────┴──────┘
       └────────────────── 字节填充（0x7D 转义）───────────────────┘
```

- **ADDR**：目标地址。宿主机 → GD32 填 `0x01`（信号机地址）；GD32 → 宿主机填 `0x00`
  （主机地址）。GD32 收到 `ADDR != 0x01` 的帧应**静默丢弃**。
- **CMD**：命令字（见 §4.4）。GD32 的应答帧在对应命令字上置 `0x80`。
- **LEN**：PAYLOAD 字节数（0..255）。
- **CRC16**：对 `ADDR | CMD | LEN | PAYLOAD`（**未填充字节**）计算，结果 2 字节
  **小端**追加。
- 帧首尾各一个 `0x7E` 定界符。

### 4.3 CRC16 与字节填充

**CRC16**：多项式 `0x1021`（CRC-16/CCITT-FALSE），初值 `0xFFFF`，**不反转输入/输出、
不异或输出**。校验向量：`CRC16("123456789") == 0x29B1`（实现后务必用此向量自测）。

C 参考实现：

```c
uint16_t crc16(const uint8_t *buf, uint16_t len) {
    uint16_t crc = 0xFFFFu;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)buf[i] << 8;
        for (uint8_t j = 0; j < 8; j++) {
            crc = (crc & 0x8000u) ? (uint16_t)((crc << 1) ^ 0x1021u)
                                  : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

**字节填充**：对 `ADDR..CRC16` 这一整段做转义，保证帧内不出现裸 `0x7E`：

| 原始字节 | 转义为 |
|---|---|
| `0x7E` | `0x7D 0x5E` |
| `0x7D` | `0x7D 0x5D` |

解码时逆过程还原；遇到非法转义对（`0x7D` 后跟 `0x5E`/`0x5D` 以外的字节）或残留的
`0x7D`，判为坏帧丢弃。坏帧**不得复位失联看门狗**（见 §5.6）。

### 4.4 命令字与载荷布局

宿主机 → GD32（CMD 低 7 位）：

| CMD | 名称 | 载荷（逐字节） | 应答 |
|---|---|---|---|
| `0x01` | PHASE_REQUEST | `[0]=相位号` `[1]=flags`（bit0=all_red_required） | `0x81` PHASE_ACK |
| `0x02` | STATUS_QUERY | 空 | `0x82` STATUS |
| `0x03` | TAKEOVER | 空 | `0x83` TAKEOVER_ACK |
| `0x04` | DETACH | 空 | `0x84` DETACH_ACK |
| `0x05` | SPECIAL | `[0]=特殊态号` | `0x85` SPECIAL_ACK |
| `0x06` | CONFIG_TIMING | 32 字节，见 §4.5 | `0x86` CONFIG_ACK |
| `0x07` | RESET | 空 | `0x87` RESET_ACK |

GD32 → 宿主机（CMD 置 `0x80`）：

| CMD | 名称 | 载荷（逐字节） |
|---|---|---|
| `0x81` | PHASE_ACK | `[0]=相位号` `[1]=结果码` |
| `0x82` | STATUS | 10 字节，见 §4.6 |
| `0x83` | TAKEOVER_ACK | `[0]=结果码` |
| `0x84` | DETACH_ACK | `[0]=结果码` |
| `0x85` | SPECIAL_ACK | `[0]=特殊态号` `[1]=结果码` |
| `0x86` | CONFIG_ACK | `[0]=结果码` |
| `0x87` | RESET_ACK | `[0]=结果码` |

**结果码**（1 字节）：

| 值 | 含义 |
|---|---|
| `0x00` OK | 已接受 / 已执行 |
| `0x01` DEFERRED | 已挂起（最小绿未到 / 清空中），稍后执行 |
| `0x02` REJECTED | 拒绝（未知相位号 / 未接管 / 处于启动或故障态） |
| `0xFF` ERROR | 参数/内部错误 |

**特殊态号**（1 字节，用于 SPECIAL 与 active_phase）：

| 值 | 含义 |
|---|---|
| `0x00` | 全红 |
| `0xFE` | 黄闪 |
| `0xFF` | 熄灯 |

**相位号**：`1=N` `2=E` `3=S` `4=W`，`0x00`=无（全红保持）。

### 4.5 CONFIG_TIMING 载荷（配时对齐）

32 字节 = 4 个相位 × 4 个 `uint16`（小端），顺序**固定**为相位 1、2、3、4；每个
相位内顺序为 **min_green、max_green、yellow、all_red**，单位**分秒（0.1 s）**：

```
偏移  0..1   min_green(相位1)
偏移  2..3   max_green(相位1)
偏移  4..5   yellow(相位1)
偏移  6..7   all_red(相位1)
偏移  8..15  相位2 同上
偏移 16..23  相位3 同上
偏移 24..31  相位4 同上
```

例：`12.0s / 30.0s / 3.0s / 1.0s` → `120 / 300 / 30 / 10`。固件收到后转毫秒
（`值 × 100`），并据此覆盖各相位配时。**配时与宿主机决策层配置必须一致**（宿主机
启动时自动下发，见 §6.1）。

### 4.6 STATUS 载荷（10 字节，执行反馈核心）

```
偏移 0    active_phase   当前相位号：1..4=N/E/S/W；0x00=无(全红保持)；
                         0xFE=黄闪；0xFF=熄灯
偏移 1    stage          灯色阶段：0=绿灯 1=黄灯 2=全红 3=黄闪 4=熄灯
偏移 2    mode           运行模式：0=NORMAL 1=LOCAL 2=FAILSAFE 3=FAULT 4=STARTUP
偏移 3    link_lost      是否失联（0/1；进入黄闪兜底时置 1）
偏移 4    fault          内部故障标志（0/1，本固件默认恒 0，保留）
偏移 5..8 phase_elapsed_ms  uint32 小端：自进入当前 (active_phase, stage) 状态起
                         的毫秒数（绿灯阶段即「绿灯已亮多久」）
偏移 9    seq            uint8 自增序号（每发一帧 STATUS 递增一次，回绕）
```

`stage` 与 `mode` 的组合约定（宿主机据此重建控制器状态）：

| 场景 | active_phase | stage | mode |
|---|---|---|---|
| 启动黄闪 | `0xFE` | 3 | 4 STARTUP |
| 启动全红 | `0x00` | 2 | 4 STARTUP |
| 正常绿灯 | 1..4 | 0 | 0 NORMAL（或 1 LOCAL） |
| 清空黄灯 | 旧相位 1..4 | 1 | 0 NORMAL（或 1 LOCAL） |
| 清空全红 | 旧相位 1..4 | 2 | 0 NORMAL（或 1 LOCAL） |
| 全红保持 | `0x00` | 2 | 0 NORMAL |
| 失联黄闪 | `0xFE` | 3 | 2 FAILSAFE（link_lost=1） |
| 熄灯 | `0xFF` | 4 | 0 NORMAL |

> `phase_elapsed_ms` 语义：**随状态切换回零**。绿灯阶段用于宿主机反推
> `相位起点 = now - phase_elapsed_ms/1000`，因此进入绿灯瞬间必须从 0 起算；
> 清空（黄/全红）期间不回零、仍指向旧相位起点亦可，宿主机只在绿灯阶段使用它。

## 5. 微型信号机逻辑要求

### 5.1 状态机（阶段）

```
                上电 / RESET
                    │
                    ▼
        ┌───────────────────────┐   5s    ┌───────────────────────┐  10s
        │ STARTUP_FLASH 黄闪    │ ───────> │ STARTUP_ALL_RED 全红  │ ─────┐
        └───────────────────────┘          └───────────────────────┘      │
                                                                          ▼
   ┌───────────────┐   黄灯到点   ┌───────────────┐   全红到点   ┌───────────────┐
   │   YELLOW 黄灯  │ <───────── │  ALL_RED 全红  │ <────────── │  GREEN 绿灯    │
   └───────┬───────┘   (清空)    └───────────────┘   (清空)     └───────┬───────┘
           │ 全红到点 → 切到 target 相位                                │ 最小绿到点且有待切
           └────────────────────────────────────────────────────────────┘ 或 最大绿到点
                                                                              │
   SPECIAL(all_red) ──> ALL_RED_HOLD（全红保持，等待相位请求/复位）             │
   SPECIAL(flash)   ──> FAILSAFE_FLASH（黄闪，等待复位）                        │
   SPECIAL(off)     ──> OFF（熄灯，等待复位）                                    │
   失联超时          ──> FAILSAFE_FLASH                                         │
```

阶段枚举（协议 `stage`）：

| 阶段 | 含义 |
|---|---|
| `STARTUP_FLASH` | 启动黄闪 5 s |
| `STARTUP_ALL_RED` | 启动全红 10 s |
| `GREEN` | 某相位绿灯中 |
| `YELLOW` | 清空黄灯（`yellow_s`） |
| `ALL_RED` | 清空全红（`all_red_s`） |
| `ALL_RED_HOLD` | 全红保持（SPECIAL all_red 触发，直到新请求/复位） |
| `FAILSAFE_FLASH` | 失联黄闪（1 Hz） |
| `OFF` | 熄灯（SPECIAL off 触发） |

### 5.2 灯色矩阵（由阶段 + 相位唯一决定）

| 阶段 | 灯态 |
|---|---|
| GREEN，相位 k | 方向 k 绿灯；其余 3 向红灯 |
| YELLOW，相位 k（清空旧相位 k） | 方向 k 黄灯 **1 Hz 闪烁**；其余 3 向红灯 |
| ALL_RED / ALL_RED_HOLD / STARTUP_ALL_RED | 4 向全红 |
| STARTUP_FLASH / FAILSAFE_FLASH | 4 向全黄，**1 Hz 闪烁**（500ms 亮 / 500ms 灭） |
| OFF | 全灭 |

### 5.3 软请求处理（`PHASE_REQUEST`）

收到相位号 `phase`（1..4）时：

1. `phase` 不在 1..4 → 应答 `REJECTED`。
2. 未接管（LOCAL）→ 应答 `REJECTED`。
3. 处于 STARTUP / FAILSAFE_FLASH / OFF → 应答 `REJECTED`。
4. 处于 GREEN：
   - `phase == 当前相位` → 应答 `OK`（已在目标，无需动作）。
   - `绿灯已亮 < 该相位 min_green` → 记入 `pending`，应答 `DEFERRED`（**最小绿硬下限**）。
   - 否则 → 进入清空（YELLOW，目标=`phase`），应答 `OK`。
5. 处于 YELLOW / ALL_RED（清空中）→ 记入 `pending`，应答 `DEFERRED`（切换完成后，
   在新相位的 min_green 到点后处理该 pending）。
6. 处于 ALL_RED_HOLD（全红保持）→ 直接进 GREEN（目标相位），应答 `OK`（已全红，
   无需再清空）。

**pending 处理**：GREEN 阶段每 tick 检查——若 `pending != 0` 且 `绿灯已亮 ≥ min_green`，
即以 pending 为目标进入清空；清空开始即清空 pending。

### 5.4 最大绿硬上限

GREEN 阶段，若 `绿灯已亮 ≥ max_green`，**必须**切换（即使无 pending）：
- 有 pending → 切到 pending；
- 无 pending → 切到**下一旋转相位**（`1→2→3→4→1`）。

### 5.5 本地 / 远程模式

- 上电默认 **LOCAL**：固定配时旋转，每相位绿灯 `CFG_LOCAL_GREEN_MS`（默认 45 s）
  后走清空并切下一相位。
- 收到 `TAKEOVER` → **REMOTE**，接受软请求。
- 收到 `DETACH` → 回到 **LOCAL**。
- `RESET` 只重跑启动序列（5s 黄闪 + 10s 全红），**保留**当前 LOCAL/REMOTE 模式；
  启动序列结束后自动进入 **GREEN，相位 1（N）**。

### 5.6 失联看门狗（数据看门狗）

- 维护「最近一次收到**有效帧**（CRC/转义正确且 ADDR=0x01）的时刻」。
- 仅 **REMOTE** 模式、且不在启动序列/黄闪态时生效：若
  `now - 最近有效帧时刻 ≥ CFG_LINK_TIMEOUT_MS`（默认 **3 s**）→ 进入
  `FAILSAFE_FLASH`（4 向黄闪 1 Hz），STATUS 报 `mode=FAILSAFE`、`link_lost=1`。
- 坏帧（CRC 错/转义错/地址错）**不**刷新该时刻。
- 恢复：失联后由宿主机重新发送 `TAKEOVER` + `RESET` 恢复（见 §6.4）；固件收到
  `RESET` 即退出黄闪、重跑启动序列。

### 5.7 默认配时（未收到 CONFIG_TIMING 前）

与宿主机 `configs/shadow.yaml` 里的 `signal_phases` 覆盖（12/80/3/1s）一致；宿主机
启动时会用 CONFIG_TIMING 再显式下发一次，双保险：

| 项 | 默认值 |
|---|---|
| min_green | 12.0 s |
| max_green | 80.0 s |
| yellow | 3.0 s |
| all_red | 1.0 s |
| 启动黄闪 | 5.0 s |
| 启动全红 | 10.0 s |
| 失联阈值 | 3.0 s |
| 黄闪半周期 | 500 ms |
| 本地固定绿灯 | 45.0 s |

## 6. 消息流程（时序）

### 6.1 启动 / 接管 / 配时对齐

```
宿主机                                      GD32 固件
   │  open 串口                                  │
   │ ── TAKEOVER ──────────────────────────────> │  mode := REMOTE
   │ <──────────────────────────── TAKEOVER_ACK  │  (结果 OK)
   │ ── RESET ─────────────────────────────────> │  重跑启动序列(5s 黄闪+10s 全红)
   │ <──────────────────────────── RESET_ACK     │
   │ ── CONFIG_TIMING(32B 分秒) ───────────────> │  覆盖各相位配时
   │ <──────────────────────────── CONFIG_ACK    │
   │                                             │  ...15s 后自动进入 GREEN(P_N)
   │   (决策层同步跑自身启动序列，双方 15s 对齐)      │
```

### 6.2 相位请求 → 清空 → 切换 → 回读

```
宿主机                                      GD32 固件
   │  决策层建议切到 P_E                          │
   │ ── PHASE_REQUEST(2) ─────────────────────> │  若 min_green 已到：
   │ <──────────────────────────── PHASE_ACK OK │  进入 YELLOW(旧相位)
   │                                             │  3s 后 ALL_RED
   │                                             │  1s 后 GREEN(P_E)
   │ ── STATUS_QUERY ─────────────────────────> │
   │ <──────────────────────────── STATUS        │  active_phase=2, stage=GREEN
   │   (决策层据 STATUS 确认已切到 P_E)             │
```

若最小绿未到：固件应答 `DEFERRED` 并挂起，最小绿到点后自动清空切换。

### 6.3 心跳 / 状态回读

宿主机每 `heartbeat.interval_s`（默认 1 s）发一次 `STATUS_QUERY`，固件应答 `STATUS`。
宿主机连续 `max_missed`（默认 3）次无应答即判链路故障并告警；固件侧则在 3 s 无
有效帧后黄闪兜底（两侧独立，双保险）。

### 6.4 失联 / 恢复

```
失联：宿主机连续无应答                    GD32 固件 3s 无有效帧 → FAILSAFE_FLASH 黄闪
恢复：宿主机重新 TAKEOVER + RESET ──────> GD32 退出黄闪、重跑启动序列
```

| 协议常量 / CRC / 填充 / 编解码 | [`host/protocol.py`](../host/protocol.py) |
| 相位映射 | [`host/phase_mapping.yaml`](../host/phase_mapping.yaml) |
| 链路（软请求/心跳/状态回读） | [`host/gd32_link.py`](../host/gd32_link.py) |
| 状态 → ControllerState | [`host/driver.py`](../host/driver.py) |
| 主循环 | [`host/main.py`](../host/main.py) |

关键对齐点：

- 相位号固定 `1=N 2=E 3=S 4=W`（不可与特殊态 `0x00/0xFE/0xFF` 冲突）。
- CONFIG_TIMING 顺序固定为相位 1..4，单位分秒 `uint16` 小端。
- STATUS 长度固定 10 字节，字段顺序不得改变。
- 宿主机只会在「切换时」发 PHASE_REQUEST；重复收到同一相位请求应视为无操作（OK）。

## 8. 验收标准（自测清单）

固件完成后，用宿主机冒烟联调前，先满足以下判据：

- [ ] `CRC16("123456789") == 0x29B1`。
- [ ] 字节填充/逆填充往返正确，帧内不出现裸 `0x7E`。
- [ ] 坏帧（CRC/转义/地址错）静默丢弃，不崩溃、不刷新失联计时。
- [ ] 上电：5 s 黄闪 → 10 s 全红 → 绿灯 P_N（相位 1）。
- [ ] 收到 TAKEOVER 后：PHASE_REQUEST 有效；LOCAL 下请求被 REJECTED。
- [ ] 最小绿硬下限：绿灯未满 min_green 的请求应答 DEFERRED，并在到点后自动切换。
- [ ] 最大绿硬上限：到 max_green 强制切换（无 pending 时按 1→2→3→4→1 旋转）。
- [ ] 清空时序：切换必经 黄灯(yellow_s) → 全红(all_red_s) → 新相位绿灯。
- [ ] 失联：拔掉串口 3 s 内进入黄闪（1 Hz），STATUS 报 `mode=FAILSAFE`、`link_lost=1`。
- [ ] RESET 重跑启动序列并保留 LOCAL/REMOTE 模式。
- [ ] 每个命令都有对应 ACK；STATUS_QUERY 应答 STATUS。
- [ ] `phase_elapsed_ms` 在进入新状态时回零，绿灯阶段单调递增（uint32）。
